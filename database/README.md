# Database migrations

Папка `database/` содержит только версионируемые миграции схемы PostgreSQL для EFA OS. Она не предназначена для локальных SQL-дампов, резервных копий или выгрузок данных.

## Порядок применения

1. Просмотреть новую миграцию и связанные архитектурные документы.
2. Проверить её в отдельной тестовой базе или через утверждённую процедуру ревью.
3. Создать резервную копию рабочей базы по действующему операционному регламенту.
4. Выполнить миграцию вручную уполномоченным оператором в порядке номеров файлов.
5. Зафиксировать в журнале развертываний дату, окружение и результат применения.

Автоматический механизм выполнения миграций пока не используется. n8n не применяет миграции и не должен выполнять DDL.

## Snapshot Layer rules

- `snapshot_runs` считаются неизменяемыми после завершения запуска (`success`, `partial` или `failed`).
- `product_snapshots` являются immutable: после записи их нельзя обновлять.
- `change_events` являются immutable: после создания они фиксируют исходный факт изменения.
- Исправления источников или поздние корректировки выполняются через новый `snapshot_run` и новые связанные снимки/события, а не через `UPDATE` старых записей.

## Именование

Используется формат:

```text
NNN_short_description.sql
```

Пример: `001_snapshot_layer_v1.sql`.

Номер состоит из трёх цифр и определяет порядок применения. После применения миграцию нельзя изменять, переименовывать или использовать повторно для новой схемы: следующая доработка получает новый номер.

## Git и безопасность

Файлы из `database/migrations/*.sql` отслеживаются Git. Локальные дампы `*.sql`, `*.dump` и резервные копии по-прежнему игнорируются через `.gitignore`.
